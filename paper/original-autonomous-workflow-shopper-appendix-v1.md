This additive appendix preserves five separately allocated development profiles.
It supplements the frozen development manuscript. Every profile keeps its own
cases and interventions; no pooled pass rate or full-study percentage follows.

Workflow V1 changed exported models after SDK graph compilation, leaving the
executing models unbound to the owned fixture. Each case recorded twelve denied
loopback connects. V2 instead preserves original models and uses an owned
public-only before-model fixture after the unchanged policy. Its raw events
cover all four original stages, retain all nine matching tool terminals, and
record no denied socket operation. The original policy short-circuits optional
after-tool observers; those missing observer records do not erase raw delivery.

Both V2 final fixture outputs remain insufficient. The frozen analyzer retains
three questions per case about target/read correspondence and its executing-node
object-identity assertion. Stage completion and successful orchestration do not
establish these task obligations. Any later diagnosis or corrected allocation
must preserve this record. This is direct original ADK; original A2A rejects the
Workflow root. An owned deterministic fixture does not establish model quality.

V1 instantiated the original shopper and native services, but its first shopper
model allocation timed out. The known 45 tokens come from access smoke only;
the failed allocation has unknown usage. Four later owned refusals allocated no
further upstream request. There were six ADK error events and no business calls,
visible messages or receipts.

V2 introduced an owned launcher regression: resolving the virtual-environment
Python link could select the global interpreter. All 182 required versions match
the retained pip report, but the actual selected-interpreter mismatch census is
absent. Its sole case stays unexecuted with zero provider calls.

V3 preserves the virtual-environment launcher and passes runtime preflight and
access smoke. Three original native services start and supply their cards. The
owned worker then rejects the changed case identifier against its frozen V1
public-facts dictionary. This is an owned metadata-wiring failure, before original
ADK execution or any shopper generation. Its one smoke allocation reports 45
tokens; all four children are reaped and the provider capture closes with no open
allocation. This does not evaluate live shopping, actor rendering, or a 120-second
shopper response. V1's failed generation remains separate from these startup
failures.

The native services and provider boundary retain original sources/SDKs, with an
owned public user actor, accounting base URL and transport/lifecycle controls.
The known-token threshold stops after responses and is not a hard token/cost cap.
