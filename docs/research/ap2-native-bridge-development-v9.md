The separate matrix evaluation kept all 104 untouched slots missing, with
zero verified captures or purchases. These are harness failures, not observed
interoperability or policy outcomes.

The independent retained-source audit
`docs/research/ap2-v8-actual-smoke-failure-peer-audit-v1.json` proves a concrete
guard conflict: the complete original source inventory reads two pinned public
SDK certificates, but the exact V8 guard rejects both paths. This deterministic
obstruction does not identify the actual omitted denied file or network caller.

V9 admits read access only to those two exact stage-hash-bound public
certificates and the exact installed certifi, gRPC and optional pip-vendored
CA bundle paths. Before installing the guard, it parses bounded certificate-only
PEM with stdlib SSL, rejects key or other non-comment material, and retains
the verified public copies and hashes. Writes through those exceptions are
refused. The separate evaluator independently parses and binds every retained
copy to its original-source or actual runtime manifest identity.

The successor records bounded denial paths and frame file/function/line
metadata, boot stages and failure traceback metadata. Declared code roots are
represented by labels; outside paths and external host names are redacted.
Loopback hosts, numeric ports and socket family/type are retained to identify
a future capability probe. Arguments, locals, source-line text, headers,
contents and environment values are excluded. Unexpected private, network
and process denials still refuse capture verification. No general IPv6 or
port-zero exception is introduced. Frozen V8 code, allocations and failures
remain unchanged, and V9 outcomes must come from a new prospective allocation.

## Two independently established outgoing maps

Both typed maps are traced from their own preserved original sources and real
published MCP schemas. Snapshots and original licenses are under
`benchmark/ap2-native-bridge-development-v9/original-outgoing-sources`.

AmirK-S `tools.ts` exposes `text`, alias and opaque handles; `a2a-client.ts`
`buildUserMessage` constructs one text Part. A fresh bridge has returned no
handle, so its input does not reinterpret the shopper's raw context ID as one.
mgcrea `tools/writes.ts` separately exposes `text`, `context_id` and `task_id`;
`client/peer.ts` builds its own one-text-Part message. Neither typed schema
exposes caller DataParts or an AP2 HTTP extension-header argument. mgcrea's
raw schema separately accepts arbitrary params but only its modern method
enum, including `SendMessage` and `GetTask`.

The actual unchanged shopper builder first creates the public native request.
The owned transport retains it before dispatch and calls only each bridge's
legal published forward surface. The original bridge CLI executes under the
sealed package bytes. The actual MCP response is retained. The caller then
stops at a disclosed `BridgeInitiationBoundary`; it does not fabricate an A2A
Task, status, receipt or MCP-to-SDK inverse. Consequently these are initiation
observations, not completed bidirectional shopper routes. The 39 prospective
bridge continuations remain unrealized if the original interface cannot reach
that boundary, and no native continuation is substituted for them.

`/a2a/merchant_agent/.well-known/agent-card.json`. The original SDK card handler
serializes the original 0.3.0 card without `supportedInterfaces`.
