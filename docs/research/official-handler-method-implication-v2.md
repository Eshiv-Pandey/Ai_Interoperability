# Bounded method implication of the official-handler controls

24 October 2026. This is a source/guard consequence of the
[v2 observations](official-handler-bridge-results-v2.md), not a new method,
comparative performance trial, full-interface certificate or passed C1 gate.

Fix the archived official handler, authored 1.0-only card, isolated executor,
public original task/context binding and the tested fixed Well done! answer.
Let S contain the inspected ordinary typed sends, the tested Amir Tasks form
acceptance, mgcrea's permitted raw SendMessage, and their read actions. A native
header-1.0 reference-bearing answer completes; the bridge goal is the same origin
task/context completed and confirmed by an authoritative original-task read.

The necessary executor completion guard is nonempty referenceTaskIds and a
case-insensitive well done prefix. taskId/contextId association alone does not
set that reference list. In the selected legal typed-send serializers, the
list is a literal empty list. Neither their exposed text/task/context arguments
nor the actual accepted string form supplies a reference field. Reads do not
execute the completion branch. Thus these typed actions fail the necessary
application guard, even though their native transport accepts header 1.0.

The permitted mgcrea raw tool can express the reference-bearing parameters,
but exposes url/method/params rather than request headers. Its rawRpc selects
the JSONRPC endpoint from the card and supplies content type; the fetch wrapper
adds authentication/User-Agent without adding A2A-Version. The official handler
defaults absence to 0.3 and rejects it against the frozen 1.0-only card before
application execution. Body params cannot repair that missing transport header.
Changing the card, proxy, source, server default or process configuration is
outside this admitted argument/action space.

For these inspected families, the accepted-request condition T and necessary
guard G therefore have this pattern:

| Family | Transport T under this fixed profile | Necessary completion guard G | T and G |
| --- | --- | --- | --- |
| Ordinary typed send / tested Tasks acceptance | True in the retained calls | False: references empty | False |
| Permitted raw SendMessage | False: no version header | Expressible in body, but not executed | False |
| Original-task read | Accepted for typed reads; raw read rejected | Does not perform completion | False |

An induction over sequences restricted to S and the isolated unchanged executor
preserves failure to reach its completion branch. This is ordinary invariant/
reachability reasoning, not a new theorem or a mechanized proof. A payload-recipe
solver and a fair exact/optimized/backward comparator with identical source,
transport, actions and contract should all find the same obstruction at this
restricted boundary. Earlier raw recovery in the custom wrapper is not an
available positive alternative here; asserting it would omit T from the question.

The argument is limited to the inspected families and assumptions. It does not
cover arbitrary full-interface policies, privileged environment changes,
alternative application contracts, new origins or external concurrency. It
does not promote four failed traces to a complete-negative certificate. In
particular, mgcrea's a2a_respond_to_task can annotate an outbound local mirror;
its source expressly distinguishes that from replying to the peer. A completed
mirror alone would fail the unchanged authoritative origin-task goal. This
operation was source-inspected, not executed as another application trial.

Sources are already preserved inside the v2 attempts and exact replay archives:
CarolReferenceExecutor in scripts/fixtures/carol-reference-v1.mjs; Amir
src/tools.ts and src/a2a-client.ts; mgcrea src/tools/writes.ts,
src/tools/request.ts, src/client/peer.ts and src/client/fetch.ts. Both pins and
source/dist closure were checked. The earlier
[source-recipe baseline](source-recipe-baseline-v0.md) states the exact
existential preimage formulation and its standard symbolic/backward comparator.

Decision: retain the new bounded fidelity result and reject these profiles as a
recovery-advantage demonstration. C1 still needs a concrete additional technical
step and a discriminating fair-comparator case; no second domain or human review
was established. Do not scale trials merely to compensate for that missing claim.
