# Preparatory novelty review

Reviewed online primary sources on 2026-10-23. This is a targeted search, not an exhaustive systematic review or proof that a first-of-its-kind claim is valid. No implementation or experiments were run. Research-paper results below are author-reported; their existence and methods were checked, but their experiments were not independently reproduced.

## Main conclusion

The project's broad claims that handoff loss is unmeasured, that no benchmark isolates a handoff against a direct baseline, and that cross-vendor collaboration is unbenchmarked are contradicted by accessible prior work. There may still be a valuable and distinct contribution in measuring actual protocol/adapter/lifecycle effects in controlled mixed-model agent systems. That narrower gap needs a documented comparison before implementation is scaled.

MultiAgentBench's coordination protocols are topologies, not native MCP/A2A wire protocols.

Other primary sources worth auditing: [Lost in Translation](https://www.teleperson.com/resources/lost-in-translation-cross-protocol-interoperability) is a May 2026 project white paper formalizing capability/lifecycle/authority/fault-preserving bridges; [Formalizing Safety, Security, and Functional Properties](https://arxiv.org/abs/2510.14133) specifies temporal-logic properties over host/task lifecycle; [HandoffProbe](https://github.com/Heaviside479/handoffprobe) is an available security-testing project for A2A-to-MCP composition. Treat these statuses separately from peer-reviewed benchmark evidence.

No relevant exact-name InteropBench agent research benchmark was found in targeted exact-name searches. This is not name clearance or evidence of scientific novelty. HandoffBench and ContinuityBench are already crowded names.

## Defensible candidate contribution

Provisional wording: A controlled, executable evaluation of how native agent protocol mappings, handoff representations, and ordered model-provider pairs interact to preserve task-relevant state, capability contracts and lifecycle semantics, with explicit attribution to producer, adapter and receiver behavior.

This is a candidate, not a proven novelty claim. A new combination of existing metrics, vendors and transports alone may be viewed as incremental. Stronger evidence would identify an overlooked semantic incompatibility, show reproducible silent loss across independently implemented adapters, and validate an actionable measurement that predicts downstream failures beyond success rate or summary similarity.

## Controls that make the result attributable

1. Hold the upstream trace/artifact and receiver model fixed when changing transport or adapter. A single-agent direct baseline changes topology, prompting and compute and cannot alone identify a protocol effect.
2. Include raw two-agent delegation with the identical payload, native protocol delegation, and composed MCP/A2A paths. Treat MCP as agent-to-tool and A2A as agent-to-agent, not interchangeable protocols. A protocol-specific wrapper is part of the treatment.
3. Include same-model diagonal and both ordered cross-model directions. Separate model developer/vendor from API hosting provider. Four models in a shared scaffold supports claims about mixed-model agents, not general vendor product interoperability.
4. Use oracle canonical state, full-history handoff, free summary and information-matched structured payload as comparator views. These controls are established prior art; cite and adapt them explicitly.
5. Run deterministic reference agents/round-trip contract checks first. Native transport that copies a payload correctly should not be expected to lose meaning. Mark intentionally removed fields as synthetic fault conditions, not intrinsic protocol defects.
6. Check independently implemented SDK mappings and, where feasible, a second adapter implementation. Otherwise loss may be an author-created adapter bug.
7. Separate state present in the receiver payload, reconstructed state, constraint-compliant behavior, tool/capability invocability, and terminal success. Probe runs should be separate from unprobed task runs or acknowledge that a state probe changes behavior.
8. Treat state/provenance/unknowns/authority/units/types/lifecycle as executable contracts where possible. A2A skill advertisement is not a promise to expose a tool schema; score capability preservation against a declared measurable common contract.
9. Repeated API samples are nested within task families; use paired family-level inference. Retain failures and negative effects. Avoid adaptive confirmatory sample sizes and post-hoc promotion of exploratory contrasts.
10. Use live end-to-end continuations for the main external-validity study; frozen boundary replay is valuable for attribution but not a complete substitute for whole-workflow evaluation.

## Recommended gate before substantial build or spending

Produce a searchable claim ledger with inclusion criteria, query log, source/version/status and a gap matrix that explicitly includes AI-NativeBench, BOUND-Handoff, Model Switching, HandoffBench, DecisionBench and CORDspec. Demonstrate a concrete task/lifecycle/capability distinction that those resources do not test. Define hypotheses, estimands and meaningful effect sizes before inspecting final test results. Build a small offline contract/adapter pilot only after user approval, then decide from pilot evidence whether to scale, narrow the claim or pivot. Publication acceptance and high novelty cannot be guaranteed by the present proposal.
