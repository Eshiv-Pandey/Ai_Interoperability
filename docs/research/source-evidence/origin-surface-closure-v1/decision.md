With writes enabled, mgcrea registers twelve tools. Read/auth/discovery,
waiting/local inventory, typed send/cancel, local response and push config
operations must all be considered alongside a2a_request. Its request enum
contains five read and four write RPC names; it is not an arbitrary method,
endpoint or HTTP-header primitive. Typed send still fixes empty references.
The request wrapper passes only url/method/params; rawRpc resolves the endpoint
from the peer card and adds content type, while its fetch wrapper adds bearer
authentication/User-Agent without adding a version header. The prior strict
handler observation remains bounded evidence for that transport premise.

The local response method calls TaskStore.applyResponse and writes its own
record, retaining direction/peer. An outbound response is explicitly documented
as mirror annotation. That method does not directly call the origin's executor.
It can change what a subsequent unrefreshed local read reports; the unchanged
benchmark goal still requires authoritative original-task/context completion.
This is documented behavior and a source distinction, not a newly measured bug
or proof of all callback/daemon behavior. Polling/waiting observes the store;
peer refresh calls GetTask rather than an application completion method.

The isolated Carol executor emits completed only through its nonempty-reference
and answer-prefix branch; cancellation emits canceled. Its ordinary text path
remains input-required. Direct-origin typed/MRTR/Tasks messages therefore
preserve the existing guard obstruction under the inspected constructor.
This is ordinary source invariant reasoning, not a new algorithm/theorem.
