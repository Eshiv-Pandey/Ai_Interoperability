## 3. Define the semantics before implementing

A contract contains only the task-relevant observable requirements: necessary operations, state transitions, task/resource identity, authorization, evidence freshness, mandatory constraints and explicitly negotiable alternatives. It is not a claim to formalize all natural-language meaning.

For a bounded route and current state, the primary target is **may-compatibility**: at least one permitted continuation exists within the declared horizon that fulfills the contract. The gate returns:

| Decision | Meaning | Required evidence |
| --- | --- | --- |
| Supported | A realizable continuation is established relative to the pinned route abstraction and stated state/time/availability assumptions | Checked mappings and discharged conditions, with evidence versions and expiry |
| Unsupported | A mandatory continuation cannot be realized through this declared route under the accepted model | A valid missing-operation/forbidden-requirement witness, or independently checked bounded no-continuation result |
| Unknown | Available evidence does not justify either conclusion | Missing/stale profiles, unobservable conditions, failed probes, timeouts or incomplete modeling, reported explicitly |

Missing advertisement without a normative negative meaning, or a failed attempt alone, does not prove unsupported. Where the pinned specification explicitly defines an absent/false capability as non-support, that rule can establish non-support for the named operation; A2A's optional-capability rules in [Section 3.3.4](https://a2a-protocol.org/v1.0.0/specification/#334-capability-validation) are an example. Safe probes of an opaque service cannot certify its arbitrary future behavior. Supported remains conditional; revalidate assumptions that can expire. Require a constructive bounded continuation certificate or a proved sufficient residual-contract condition checked independently. An empty residual list or advertised flags alone do not establish realizability. A bounded no-path certificate also requires a complete model/profile for the relevant actions within that bound.

Freeze horizon units (operations and/or elapsed time), starting state, legal actions, principal/resource scope and timing/availability assumptions consistently across gate and oracle before comparison.

Keep three questions separate: whether a route admits a legal completion, whether modeled mappings preserve specified safety properties, and whether the LLM actually follows a successful policy. Existential reachability cannot prove universal progress or unrestricted LLM correctness. Any safety statement quantifies over explicitly allowed modeled traces; progress needs stated environment/availability/fairness assumptions. Stronger strategy-versus-environment progress guarantees are outside the initial scope.

Composition also needs compatible adjacent contracts and preserved cross-edge assumptions. A “local checks pass, global route fails” case must name the dependency omitted by those cheaper local checks. It cannot refute a sound composition theorem whose assumptions are all satisfied.

Pin the protocol profiles actually tested. [MCP Tasks](https://modelcontextprotocol.io/extensions/tasks/overview) supports durable task handles, input and cooperative cancellation; [A2A](https://a2a-protocol.org/v1.0.0/specification/) has its own task semantics. MCP tools and A2A skills are different declarations. Optional non-support is not a core-protocol defect, and cooperative cancellation does not promise immediate termination.

## 4. Smallest method worth building

Use a deterministic admission procedure after runtime requirement extraction. Avoid training a new router, clarifier or model, or inventing another transport.

1. Extract requirements from ordinary user/source documents, sender-visible tool results and negotiated manifests. Record ambiguity and missing evidence.
2. Describe each pinned adapter profile with exposed operations, guarded transitions, identity/reference mappings, principals and explicit assumptions.
3. Propagate residual obligations through the route, retaining dependencies between operations, handles, resources, authorization and time.
4. Discharge obligations using versioned profiles, ordinary evidence and safe bounded probes. Retain unresolved conditions.
5. Return a supported residual contract, an independently checkable unsupported witness, or an unknown reason. Define the witness reduction procedure without claiming globally minimal proof size.
6. Resolve only through authorized retrieval/materialization, a permitted native/fallback route, or an explicit alternative contract. Revalidate expiring conditions at continuation time.

Illustrative pressure case: a route exposes both resume and artifact retrieval, but the last bridge returns a handle in a namespace the caller cannot resolve and an artifact URI inaccessible to the receiving principal. A feature checklist passes; the required same-task continuation may fail. This is a hypothesis to test against real implementations, not an already discovered defect.

Mandatory requirements cannot be silently weakened. Materialization cannot expose unauthorized data. An alternative contract must be recorded as an agreed alternative, not scored as success on the original unmet contract.

Keep runtime contract **C_runtime** separate from evaluator-private **C_gold**. The practical method sees normal sources, profiles and probes. Gold contains independently authored requirements and finite-reference state for grading only. Evaluate extraction omissions; do not give the method hidden gold to make it look reliable.

Evaluate the admission algorithm against an independent oracle for the exact C_runtime supplied to it; evaluate the complete extraction/admission pipeline against C_gold separately. An omitted gold requirement is an extraction/pipeline failure, not automatically an unsound gate decision on its supplied contract.

The finite oracle must be authored independently of the gate, using separate state/transition logic and reference trajectories. Cross-check tiny worlds exhaustively and replay against actual SDK/wire behavior. Agreement between two copies of the same mapping code is not independent validation.

## 8. Strong comparators without model expense

Keep the following deterministic comparators:

1. Schema/type and advertised-feature checks.
2. Required-field/contract linting and per-edge lifecycle checks.
3. Exact bounded product **may-reachability**, with the same runtime-visible profile, contract, evidence and horizon.
4. Symbolic/backward and credible cached/incremental analysis where checking-cost improvements are claimed.
5. Applicable AgentThread/CONTINUITY-style checks and quotient-based residual contracts on shared expressible fragments.
6. A separately authored evaluator-private finite oracle for correctness grading.

The private oracle is not the same code renamed as a baseline. Released systems or scoped adaptations must be identified accurately.

A complete exact reachability checker cannot be outperformed on correctness within its accepted model. The new method must earn a distinction through checking cost, evidence/query reuse, compact independently checkable certificates, or useful coverage under a declared checking budget. Standard predecessor propagation, three labels or a new protocol name alone are insufficient novelty.

Primary core outcomes: oracle agreement for the supplied contract, false acceptance/rejection, unknowns, supported coverage, valid witnesses/certificates and checking/evidence-query cost. Keep gate correctness on C_runtime separate from extraction/pipeline performance against C_gold.

Manually specified runtime contracts are acceptable for the core if described as deployment-supplied contracts. They do not establish reliable automatic extraction. Natural-language extraction receives a small separate diagnostic and is reported with its omissions.

Mandatory component controls are dependency omission, per-edge-only checking, no revalidation, no permitted resolution, and exact versus runtime-derived contracts. Reuse frozen traces only where the intervention leaves downstream state unchanged; otherwise perform a fresh local controlled replay.
