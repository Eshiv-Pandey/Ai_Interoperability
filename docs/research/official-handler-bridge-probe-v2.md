## Why v2 exists

The [v1 preparation](official-handler-bridge-results-v1.partial.md) had one
retained B1 setup failure at Node spawnSync git EPERM. No native control, bridge,
MCP request or evaluator read executed. B2-B4 were unexecuted. Keep that record,
the partial check/replay and post-setup matching source snapshots unchanged.
A local Python process-capability check successfully ran the same Git command
without changing permissions or proxy settings. V2 changes the process supervisor;
it cannot replace or erase v1. These are still the first prospective service
cases for this new official-handler bridge comparison.

## Actual process and I/O boundary

The provided command tool launches supervise_official_bridge_v2.py. Python
subprocess Git commands record both exact HEADs and clean tracked status before
the Node worker starts. The worker verifies and archives the receipt and freezes
its source, checker, supervisor, relay, preload, original callers, source/dist,
direct runtime packages and complete official HTTP environment before SDK imports.

Python launches the original bridge CLI with genuine binary stdin/stdout pipes.
A harness-only relay forwards bytes between those actual pipes and the existing
Node caller event interface. It creates no application/tool reply, mapping,
identifier, header, method, field, endpoint or decision. Every requested stdin
write and successful actual pipe write is retained; every actual stdout read and
forwarded chunk is retained. The checker compares those pairs and reconstructs
the complete mgcrea request/response byte streams from real caller exchanges.
Amir's MCP calls remain genuine HTTP; its stdout is only CLI diagnostics.

Python uses isolated environment variables, hidden process windows and the
same declared bridge configuration. Dynamic configuration is frozen before
actual bridge startup. The relay records real PIDs, command, source receipt,
write acknowledgments and terminal process exit. No paid model, external service,
network beyond loopback, transport repair or additional protocol direction is used.

For shutdown, Python writes one PID/run-bound exclusive control file inside the
attempt. The read-only preload observes it, records the original CLI SIGTERM
listener count and invokes the unchanged shutdown handler. Python sends the
actual terminal exit through the relay; the worker waits for it, then closes
the official server and checks source/runtime hashes. Unexpected exits, setup
errors, protocol failures and exact-PID fallback kills remain failed/partial
attempts. No timeout by itself authorizes restarting a process or case.

Native/request bounds remain the v1 bounds. An overall180s supervisor deadline
exists only to terminate a stuck harness safely; it does not extend a task's
admission horizon or justify a favorable rerun. Controller plumbing adds
instrumentation overhead; no latency or efficiency claim is made.

## Independent checking and preservation

Use exclusive attempt paths and retain every failure. The v2 checker adapts the
separately agent-authored v1 checker with disclosed integrating-assistant changes.
It imports no SDK/capture driver and reuses raw-entity, ingress, binding, source,
profile, lifecycle and cost checks. Added checks validate actual Git receipts,
Python launch identity, pipe read/write/forward byte equality and stdio stream
reconstruction. Valid evidence and expected outcomes remain distinct; partial
records cannot pass a complete claim.

Archive the Node attempt, supervisor attempt, frozen checker and replay. Run
isolated Python checking and in-memory mutations on those same preserved bytes,
without repeating any SDK/service/bridge case. Include the earlier binding,
reference, artifact, header, status, order, cost, closure and snapshot mutations,
plus altered relay-byte/receipt/process-control mutations.

The integrating-assistant adaptation is implemented in
scripts/check_official_handler_bridge_v2.py and
scripts/replay_official_handler_bridge_v2.py. The latter parses its isolated
worker before execution and archives the supervisor directory alongside the Node
attempt. It copies the attempt's frozen checker/replay bytes. For a complete
expected-outcome record, replay attempts 25 mutations for B1/B2 and 26 for B3/B4;
the extra mgcrea mutation targets an actual stdin write. Coherent altered read/
forward pairs and reordered real output chunks must also fail. Mutation setup
errors never count as rejected claims. Actual reader EOF events must precede
the relayed terminal exit. This is software checking by the integrating assistant,
not a new independent or human scientific review.

No scientific gate changes follow solely from these controls. C1 still needs
a demonstrated distinction against strong comparators, a qualifying second
domain is missing, and human novelty/feasibility review remains uncompleted.
