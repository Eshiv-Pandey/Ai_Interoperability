# Independent software review of historical status projection v1

Prepared 24 October 2026 before the new Carol bridge captures. This is an AI-authored software review; independent human review remains pending. CP2 stays open and checkpoint progress remains 5%. Passing controls establishes neither a new algorithm nor C1 novelty, natural failure prevalence, a prospective non-support result, or completion of a scientific gate.

The frozen contract is [reference-bridge-probe-v1.md](reference-bridge-probe-v1.md), together with [finite-model-v1.md](finite-model-v1.md). The source-backed paths inspected were AmirK-S `58eff9da469bccdc432bf164662727947de646b4` (`envelope.ts`, `lifecycle.ts`, Tasks handlers) and mgcrea `c4d9d3c57c1746abbf9f6aadd3a9912d464eb1f5` (`tools/request.ts`, the preserved request source, `client/shape.ts`). The disclosed authored Carol port remains `b6b6492ee5c27cf5db0474054b0f18a8feafe0859d9faaa4fd67946c7768626d`.

`src/interoperability/status_projection_checker.py` provides pure `check_status_projection(trace, projection)` and `check_status_native_sidecar(trace, records)` functions. The checker imports Python standard-library modules only. It does not import the new projector, the previous projector/checker, an extractor, baseline, oracle, finite-model helper, source program, filesystem or transport. The previous projection format was read to establish event/manifest field names; extraction and validation here were separately authored from the status contract and pinned field paths. The tests state their expected projection fields and graph independently; they do not obtain expected results from the projector. The tests may call the independent finite oracle to check the decision implied by a manually stated model.

The public checker validates strict UTF-8 bodies, duplicate-free JSON, raw/parsed agreement, mandatory response hashes, supplied request hashes, supplied byte/base64 ledgers, response IDs and serial UTC/monotonic intervals across the entire trace. It validates the route/source pin and actual route-specific MCP profile: Amir modern `server/discover` plus per-request revision/capabilities and matching HTTP revision/method/tool-or-task-name headers; mgcrea one 2025-11-25 initialize request/reply plus its initialized notification before task actions. Header names are case-insensitive and duplicate case variants are rejected. Supplied variant IDs must agree with their route; R1 omits the Tasks extension on every request, while R2 declares it on every request. Setup uses an explicit read-only whitelist and cannot hide unknown operations, RPC/tool/HTTP errors or missing result objects. The checker preserves setup in the source digest and archival clock, rejects missing paired replies, and distinguishes outer MCP IDs from raw native JSON-RPC IDs. Explicit SSE framing is decoded only for a declared SSE response.

The first complete typed ordinary task/context view supplies the original references. Earlier nonempty public task/context references must agree; an opaque modern creation handle cannot be silently replaced by another task when the ordinary read supplies context. Missing values remain absent, while supplied string/integer/boolean/null observable values remain literal. Amir opaque handles and public mgcrea native IDs retain their separate namespaces. Request targets do not fill missing response context.

Every selected task read/action from the prefix is present in the exact serial graph, including raw `a2a_request/SendMessage` and `a2a_request/GetTask`. Cancellation, decline, other raw methods, unmodelled later actions and error replies require a separately declared model and are rejected. Raw MCP text contains another strict native JSON-RPC envelope: SendMessage reads `result.task`, GetTask reads `result`, and an inner error is rejected even when the outer MCP tool is successful. Known uppercase states use explicit pinned mappings, native null is a known null, and unknown/numeric native states require another declared projection. Amir outer modern `completed` is delivery only; a nested ordinary task view supplies logical status/context, and an acknowledgement supplies no invented completion. A sole `a2aState` does not manufacture an absent ordinary `status`.

The checked finite goal contains exactly three predicates: logical completed status, returned task equal to original task, and returned context equal to original context. The two invariants require the recorded original request target and correct namespace. There is no artifact predicate or private identifier in this projection. The exact manifest has `evidence.complete=false`, a zero-width fixed archival clock after the last recorded response, and a horizon equal to the recorded transition count. Waiting-only evidence remains unknown; later-clock evaluation abstains. A historical completed path can be supported conditionally on this incomplete recorded evidence.

The separate native checker accepts only explicitly supplied private metadata/records. It supports both earlier flat records and the new logger's paired `request-started`/`exchange-completed` records, with declared shutdown/exit records. It validates body hashes, native JSON-RPC correlation, dispatch method/text, actual task/context targets, opaque-handle binding, native status versus public status, and mandatory peer-refreshed GetTask evidence. Request initiation must belong to a unique MCP interval; native response completion may follow an asynchronous acknowledgement. Raw request params/replies must equal their public nested counterpart. Absence of `A2A-Version` is retained and accepted only with the captured matching JSON-RPC 1.0 agent-card interface; no header or private public reference is invented.
