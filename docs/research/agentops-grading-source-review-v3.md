## Closed implementation checks

The reply/dependency, sampled-state and boundary collectors had separate AI
source reviews and independently audited 41/24/16-test captures. The answer/schema
implementation had a separate AI source review before its 35-test capture. The
root agent completed the integrated assessor and CLI source review after their
authors' peer sessions became unavailable. Their captured primary suites passed
13 and 7 tests. A separate peer receipt audit of these three newest captures is
pending; their local static receipt audits are verified.

1. The original configured trajectory metric remains the frozen v1 call-only
   metric, with ordered required subsequence, recursive argument subset and
   extra-call behavior preserved. The integrated assessor binds exact original
   application/evaluator projections and required obligation sequences.
2. Reply/dependency checks preserve duplicate and partial observations. Stronger
   support requires uniquely attributed success in an earlier original yield.
   Confirmation pauses, missing resources and execution-shaped success remain
   distinct. Call/reply/value consistency is not causal execution proof.
3. Sampled business state preserves the original schema, rows, keys and sequence.
   Memory structural insertion is separate from intended text, displayed replies
   and original sanitizer fidelity. Missing evidence remains unknown or pending.
4. The boundary collector binds instance/bootstrap/client plans, source family,
   endpoint, source prompt/context and actual request/response entities. It
   rejects polling after a terminal or confirmation-pause observation. A distinct
   successful original readiness response supplies the startup baseline. Archived
   stores reject unsupported sidecars/headers before connecting. Exact captured
   reader source bytes execute without consulting cached bytecode.
5. Report checks retain observed model text, original parts and provenance;
   strict JSON and declared schema projection have separate labels. Direct
   report fields use the actual earlier successful incident reply. Pydantic
   equivalence, semantic adequacy and paraphrase are unproved. Arbitrary caller
   workflow path labels cannot establish original stage identity: original stage
   order remains unknown, with supplied-candidate ordering separately labeled.
6. A missing-text confirmation pause requires the matching source-shaped request
   to be the final sole tool observation in the selected node, without competing
   partial or output surfaces. Ambiguity stays unknown. Harmless empty SDK user
   metadata defaults are accepted; nonempty unsupported metadata is not erased.
7. The v2 CLI pins source projections/obligations/design, compiles pre-read helper
   bytes in dependency order, and binds journal receipt/event/file identities to
   the retained instance and bootstrap receipts. The executed business-reader
   identity must match its pre-read source binding. Input/source/instance bytes
   and directories are checked again before exclusive pending fsync/close and
   atomic final publication. Publication failure cannot produce an eligible
   final receipt. These are artifact consistency and sampled immutability checks.
8. Captures explicitly select only new primary test files. Test-named fixture
   helpers are retained but their suites are not discovered. The static audit
   additionally compares every logged test identity to primary-source AST
   declarations, exact machine/text counts, hashes and file/directory membership.
   No test, SDK, database, model or original application runs in that audit.
