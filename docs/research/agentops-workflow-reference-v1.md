## Actual route and disclosed interventions

Original `agent.server._a2a_agent` refuses a `Workflow` root and requires
`AGENT_ENTRYPOINT=agent`. This allocation consequently uses the original
`composition.app`, selected with `AGENT_ENTRYPOINT=workflow`, through official
ADK `InMemoryRunner`. It does not qualify the original A2A server, an independent
bridge, native network behavior or a durable task continuation. Original graph
topology is exactly `START`, `plan`, `investigate`, `evidence_review`, `recommend`.

Each node retains its original instruction, exact read-only tool surface and
absent per-node policy callbacks. Only its model is replaced with a separately
attributed deterministic public-only `BaseLlm`. The fixture receives only that
node's actual governed model input and returned tool responses. It receives no
private evaluator answers. Investigative identifiers derive from actual source
results; request assertions remain distinct from observations across successive
contextual JSON handoffs. This format is an owned model response, not a new
original output schema or modified instruction. A missing or incompatible
actual predecessor representation is retained as a failed/insufficient result.

The actual original App keeps its single original policy plugin first. One
owned observational App plugin is appended, records actual stage entry/exit and
tool before/after identities/results, and always returns `None`. No callback or
policy is added to individual nodes. The original policy may transform inputs
and tool outputs as usual. Observational journals, actual model requests and raw
official events are retained separately.

ADK dispatches plugin callbacks until the first non-`None` result. Original
`secure_tool_output` may return a replacement dictionary, so the appended
observer's after-tool hook can legitimately be skipped. Its after-hook journal
is optional. Terminal completeness and delivered source data are reconstructed
from raw official SDK function-response events, joined to actual function-call
IDs and node authors. These are explicitly post-policy delivered values, not
claims that the underlying untransformed business result was observed. Policy
ordering and source are preserved.

The two public tasks and initial fixture recipes remain unchanged. The public
write-switch value remains false; the original workflow's restricted tool
surface provides the read-only boundary. No action, note or confirmation is
injected. The driver invokes the original explicit runtime-database preparation
boundary before the read-only task, then compares complete before/after database
rows and copied seed bytes. Native/provider socket operations are denied before
operation. The previously reviewed urllib3 cold-import intervention skips its
IPv6 capability probe and restores the original flag before App initialization.
There are no provider calls. Original source/model/transport intervention limits
remain explicit even if this engineering reference completes.

## Bounds, retention and analysis

Each original node is limited to eight owned model responses; the worker has a
24-response global bound and 80 raw-event bound. Each of the two worker attempts
has a 150-second outer timeout. A normal h09 fixture uses one list plus four
exact evidence reads in investigation, four exact re-reads in review and one
runbook reload in recommendation. A resolved conflicting h10 request preserves
the original target and asks for clarification without a write. Those are
prospective model recipes, not guaranteed runtime outcomes.

The separate standard-library analyzer reconstructs both cases from raw official
events, model/function outputs, observational ToolContexts and complete state
rows. It checks actual four-stage execution/order, tool correspondence and
surface restrictions, source-derived target selection, and final raw event
presence. Missing stages, failed workers, altered targets, incomplete tool
terminals and adverse state effects remain partial/inconsistent. This is
development correspondence analysis, not a human semantic grade. Original bank
qualification, actual model quality and full three-path study remain open.

Constructed short-circuit controls verify that all appended after-tool hooks may
be absent while complete raw official function-response deliveries remain
verifiable, and that missing raw deliveries still produce a partial result.
They execute no original policy, SDK or application.

The hosted workflow stages original source, runs constructed controls and checks
prospective input hashes, then executes once into
`runs/ci-agentops-workflow-reference-v1/<run-id>-<attempt>/`. It always uploads
that new allocation and source-staging evidence, including failed attempts.
Root owns its independent review, freeze, dispatch, retention and integration.
